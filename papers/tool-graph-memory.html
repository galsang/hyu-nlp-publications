Rethinking the Role of Tool Graph Memory in Multi-Turn Tool Use

arXiv 2026
Uiji Hwang, Richeng Xuan, Taeuk Kim

One-Line Summary

A systematic re-examination of tool graph memory (ToolNet, H-EPM) across nine open-weight models and two multi-turn tool-use benchmarks shows that it rarely improves significantly over a memory-free agent, that its occasional gains cost 2.72× the LLM calls and arise from extra tool-calling attempts rather than the memory's (often incorrect) next-tool suggestions, and that storing the same experience as natural-language insight memory performs best in most settings with almost no additional LLM calls (1.03×).

Background & Motivation

LLM agents increasingly solve complex tasks by calling external tools over multiple turns, and memory lets them retain and reuse experience from previous interactions. One prominent design is tool graph memory: successful trajectories are turned into a graph whose nodes are tools and whose weighted, directed edges are tool transitions. ToolNet shows the agent only the successors of the previously invoked tool, using edge weights as preference scores. H-EPM keeps the full tool set and treats the weighted transitions as procedural memory and the edge-attached context summaries as episodic memory; at each step the agent may summarize its state and then receives the two successor tools whose stored contexts best match that summary (or the two highest-weight successors otherwise).

Both methods provide step-level next-tool suggestions. Whether such guidance consistently helps agents across multi-turn interactions, however, had not been established with repeated runs, paired significance tests, or accounting of the extra computation it incurs.

Key questions: (1) Does tool graph memory consistently improve over memory-free baselines across model families, sizes, and benchmarks? (2) How much additional computation does it cost in LLM calls and tokens? (3) Where gains do exist, do they really come from the memory's suggestions? (4) Which failure modes remain even when the suggested tool is always correct, and what form of guidance would resolve them?

The answers turn out to be surprising: the gains are rare, expensive, and largely attributable to the agent simply attempting more tool calls, while even oracle-correct suggestions leave many failures untouched. This motivates rethinking memory as a soft prior about what to do in a situation rather than a prescription of the next tool.

Analysis & Proposed Method

The paper proceeds in four stages, moving from a broad empirical audit of tool graph memory to a lightweight alternative, insight memory, built from the very same experience.

1
Large-Scale Evaluation with Significance Testing
Agents with ToolNet or H-EPM are compared against a memory-free agent (Base) on ToolSandbox (207 test scenarios) and the multi-turn subset of BFCL-v4 (160 tasks), using nine open-weight models from the Qwen, Gemma, Mistral, and gpt-oss families (2B to 120B parameters) plus GPT-4.1 and GPT-5.1 on ToolSandbox. Every method is run three times with greedy decoding, and gains are checked with two-sided paired t-tests over scenarios. Cost is measured in LLM calls and tokens per scenario.
2
Manual Analysis of Decisive Turns
On Mistral-Small-3.2-24B, every scenario that fails under Base but succeeds with H-EPM is inspected by hand. Each decisive turn (the turn that accounts for the outcome difference) is annotated for whether the suggestion was correct and whether the agent followed it. The same annotation is applied to scenarios that H-EPM degrades, revealing that 98% of suggestions at those decisive turns are incorrect.
3
Controlled Ablations of the Suggestions
Keeping the rest of H-EPM fixed, the suggested tools are (a) replaced with random tools, (b) replaced with the correct tool as an oracle upper bound, or (c) removed entirely; the summarization step is also ablated. As a graph-free control, Base receives a single instruction: “Do not give a final answer or give up until you have tried the available tools” (Base + instruction). Tool calls are counted separately for scenarios each condition flips to success versus those that still fail.
4
Failure-Mode Taxonomy under the Oracle
Remaining oracle failures are classified by the earliest wrong decision: call necessity (whether to call a tool at all), tool selection (which tool), dependency (when to call it, i.e., prerequisites), and argument (with what values). With the correct next tool always suggested, tool selection errors almost vanish (4% of failures), so the remaining failures concern what to do in a situation, which a graph of tool transitions cannot encode.
5
Insight Memory
H-EPM's episodic summaries, including those of failed trajectories, are embedded with all-MiniLM-L6-v2 and clustered with k-means (k chosen from 15 candidates between 5 and 150 by silhouette score). The agent model distills each cluster into insights about what to do and what to avoid. At every model call, the five most recent messages are embedded, matched against all summaries, and the insights of the clusters of the two most similar summaries are added to the system prompt. No training is required, retrieval needs no LLM call (median 15–17 ms per turn), and the graph itself is never used.

  • Tool graph memory rarely helps: ToolNet underperforms Base in most cases, including all nine models on BFCL-v4, with a statistically significant drop in 12 settings. H-EPM is numerically above Base in most settings but its gain is significant in only four.
  • Gains are expensive: H-EPM uses on average 2.72× as many LLM calls and 2.21× as many tokens as Base on ToolSandbox, with a similar increase in LLM calls on BFCL-v4. Neither method offers a better performance–cost trade-off than Base.
  • Suggestions are mostly wrong: In scenarios that H-EPM fixes on Mistral-Small-3.2-24B, the suggestion is correct in only 30% of decisive turns; in another 50% the agent calls the necessary tool on its own despite a wrong suggestion. In degraded scenarios, 98% of suggestions at decisive turns are incorrect.
  • The benefit comes from more tool calls: Replacing suggestions with random tools or removing them entirely performs comparably to H-EPM (and w/o suggestions beats it on two of three models). Scenarios flipped to success make roughly twice as many tool calls as Base, and a single “keep trying tools” instruction matches or exceeds H-EPM with almost no extra LLM calls.
  • Correct next tools are not enough: Even the oracle leaves many failures; with tool selection errors reduced to 4%, the rest stem from call necessity (e.g., giving up without a tool call), dependency, and argument errors.
  • Insight memory is the best trade-off: Insight is best in most settings of Table 1, significant over Base in far more settings than either tool graph memory, attains the highest pass@3 in almost all settings, keeps LLM calls at 1.03× Base, and recovers most scenarios H-EPM degrades, including every dependency and argument failure. Combining it with H-EPM is worse on seven of nine models and needs 2.68× the LLM calls, while Insight + instruction is the best non-oracle condition on all three ablation models and even surpasses the oracle on gpt-oss-20b.

Why It Matters

Memory for tool-use agents has gravitated toward structured representations that prescribe the next action. This paper provides the first rigorous, significance-tested audit of that idea for tool graph memory and shows that the apparent benefit is largely an artifact of extra computation: the same boost is available from a one-line instruction, and the graph's guidance is more often misleading than helpful.

  • Rigor for the memory literature. Repeated runs, paired tests, and cost accounting across nine open-weight and two frontier models expose how easily single-run gains can be mistaken for a real effect, setting a higher evidentiary bar for future agent-memory claims.
  • A diagnosis, not just a negative result. The failure taxonomy (call necessity, tool selection, dependency, argument) explains why even perfect next-tool suggestions fall short: tool transitions do not tell an agent whether, when, or with what arguments to call a tool.
  • A practical, generalizable alternative. Insight memory distills the same episodic experience into situation-level semantic knowledge, requires no training, adds negligible inference cost, and transfers across scenarios. Its advantage also holds for ExpeL-style insights and for insights built from successful trajectories only, supporting the broader conclusion that memory works better as a soft prior than as a prescription of the next tool.
