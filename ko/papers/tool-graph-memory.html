Rethinking the Role of Tool Graph Memory in Multi-Turn Tool Use

arXiv 2026
Uiji Hwang, Richeng Xuan, Taeuk Kim

한줄 요약

도구 그래프 메모리(tool graph memory; ToolNet, H-EPM)를 9개의 오픈 가중치 모델과 2개의 다중 턴 도구 사용 벤치마크에서 체계적으로 재검토한 결과, 메모리가 없는 에이전트 대비 유의미한 성능 향상은 드물었고, 간혹 나타나는 이득도 2.72배의 LLM 호출을 요구하며 메모리의 (대부분 틀린) 다음 도구 제안이 아니라 단순히 도구 호출 시도가 늘어난 데서 비롯됨을 보였습니다. 같은 경험을 자연어 인사이트 메모리(insight memory)로 저장하면 추가 LLM 호출이 거의 없이(1.03배) 대부분의 설정에서 가장 좋은 성능을 얻습니다.

배경 및 동기

LLM 에이전트는 외부 도구를 여러 턴에 걸쳐 호출하며 복잡한 과제를 해결하고, 메모리는 이전 상호작용에서 얻은 경험을 보존하고 재사용할 수 있게 합니다. 대표적인 설계 중 하나가 도구 그래프 메모리입니다. 성공한 궤적(trajectory)으로부터 도구를 노드로, 도구 간 전이를 가중치가 있는 방향 간선으로 하는 그래프를 구축합니다. ToolNet은 직전에 호출한 도구의 후속 도구만 에이전트에 보여 주며 간선 가중치를 선호 점수로 사용합니다. H-EPM은 전체 도구 집합을 유지하되, 가중 전이를 절차 기억(procedural memory)으로, 간선에 붙은 문맥 요약을 일화 기억(episodic memory)으로 활용합니다. 매 단계 에이전트는 현재 상태를 요약할지 결정하고, 요약하면 그 요약과 가장 잘 맞는 저장 문맥을 가진 후속 도구 2개를, 그렇지 않으면 전이 가중치가 가장 높은 후속 도구 2개를 제안받습니다.

두 방법 모두 단계 수준의 다음 도구 제안(next-tool suggestion)을 제공합니다. 그러나 이러한 안내가 다중 턴 상호작용 전반에서 일관되게 도움이 되는지는 반복 실행, 쌍체 유의성 검정, 추가 계산 비용의 측정을 거쳐 확인된 적이 없었습니다.

핵심 질문: (1) 도구 그래프 메모리는 모델 계열, 크기, 벤치마크에 걸쳐 메모리 없는 베이스라인보다 일관되게 좋은가? (2) LLM 호출과 토큰 측면에서 추가 비용은 얼마나 드는가? (3) 이득이 존재할 때, 그것은 정말 메모리의 제안에서 비롯되는가? (4) 제안된 도구가 항상 정답이어도 남는 실패 유형은 무엇이며, 이를 해결하려면 어떤 형태의 안내가 필요한가?

답은 예상 밖이었습니다. 이득은 드물고 비싸며 대부분 에이전트가 단순히 더 많은 도구 호출을 시도한 결과였고, 정답 도구를 제안하는 오라클조차 많은 실패를 해결하지 못했습니다. 이는 메모리를 다음 도구에 대한 처방이 아니라 해당 상황에서 무엇을 해야 하는지에 대한 부드러운 사전 지식(soft prior)으로 다시 생각하도록 이끕니다.

분석 및 제안 방법

논문은 도구 그래프 메모리에 대한 광범위한 실증 검토에서 출발하여, 동일한 경험으로부터 구축되는 경량 대안인 인사이트 메모리에 이르기까지 네 단계로 진행됩니다.

1
유의성 검정을 동반한 대규모 평가
ToolNet 또는 H-EPM을 장착한 에이전트를 메모리 없는 에이전트(Base)와 ToolSandbox(테스트 시나리오 207개)와 BFCL-v4 다중 턴 부분집합(과제 160개)에서 비교합니다. Qwen, Gemma, Mistral, gpt-oss 계열의 2B–120B 오픈 가중치 모델 9개에 더해 ToolSandbox에서는 GPT-4.1과 GPT-5.1도 평가합니다. 모든 방법은 탐욕적 디코딩으로 3회 실행하고, 시나리오 단위의 양측 쌍체 t-검정으로 이득의 유의성을 확인하며, 시나리오당 LLM 호출 수와 토큰 수로 비용을 측정합니다.
2
결정적 턴에 대한 수동 분석
Mistral-Small-3.2-24B에서 Base는 실패하지만 H-EPM은 성공하는 모든 시나리오의 전체 궤적을 직접 검토합니다. 결과 차이를 만든 결정적 턴(decisive turn)마다 제안이 정답이었는지, 에이전트가 그 제안을 따랐는지를 주석합니다. 같은 주석을 H-EPM이 성능을 떨어뜨린 시나리오에도 적용하여, 해당 결정적 턴의 제안 중 98%가 틀렸음을 확인합니다.
3
제안에 대한 통제 절제 실험
H-EPM의 나머지 구성 요소는 고정한 채 제안 도구를 (a) 무작위 도구로 교체하거나, (b) 상한선으로서 정답 도구로 교체하는 오라클을 두거나, (c) 제안 자체를 제거하고, 요약 단계도 별도로 절제합니다. 그래프 없는 통제 조건으로 Base에 단 하나의 지시문 “사용 가능한 도구를 시도해 보기 전에는 최종 답변을 하거나 포기하지 말 것”을 추가합니다(Base + instruction). 각 조건이 실패를 성공으로 뒤집은 시나리오와 여전히 실패하는 시나리오로 나누어 도구 호출 수를 집계합니다.
4
오라클 하에서의 실패 유형 분류
오라클에서도 남는 실패를 가장 먼저 잘못된 결정에 따라 분류합니다: 호출 필요성(도구를 호출할지 여부), 도구 선택(어떤 도구를), 의존성(언제, 즉 선행 조건 충족 여부), 인자(어떤 값으로). 정답 다음 도구가 항상 제안되면 도구 선택 오류는 거의 사라지지만(실패의 4%), 나머지 실패는 그 상황에서 무엇을 해야 하는가에 관한 것이어서 도구 전이 그래프로는 담을 수 없습니다.
5
인사이트 메모리
H-EPM의 일화 요약(실패한 궤적의 요약 포함)을 all-MiniLM-L6-v2로 임베딩하고 k-means로 군집화합니다(k는 5–150 범위의 후보 15개 중 실루엣 점수로 선택). 에이전트 모델이 각 군집으로부터 무엇을 해야 하고 무엇을 피해야 하는지를 인사이트로 추출합니다. 매 모델 호출 시 최근 메시지 5개를 임베딩하여 모든 요약과 비교하고, 가장 유사한 요약 2개가 속한 군집의 인사이트를 시스템 프롬프트에 추가합니다. 학습이 필요 없고, 검색에 LLM 호출이 들지 않으며(턴당 중앙값 15–17ms), 그래프 자체는 전혀 사용하지 않습니다.

  • 도구 그래프 메모리는 거의 도움이 되지 않음: ToolNet은 BFCL-v4의 9개 모델 전부를 포함해 대부분의 경우 Base보다 낮았고, 12개 설정에서 통계적으로 유의한 하락을 보였습니다. H-EPM은 대부분의 설정에서 수치상 Base를 웃돌지만 유의한 이득은 4개 설정뿐입니다.
  • 이득은 비쌈: H-EPM은 ToolSandbox에서 Base 대비 평균 2.72배의 LLM 호출과 2.21배의 토큰을 사용하며, BFCL-v4에서도 LLM 호출이 비슷하게 증가합니다. 두 방법 모두 Base보다 나은 성능–비용 트레이드오프를 제공하지 못합니다.
  • 제안은 대부분 틀림: Mistral-Small-3.2-24B에서 H-EPM이 성공으로 바꾼 시나리오의 결정적 턴 중 제안이 정답인 경우는 30%에 불과하고, 또 다른 50%에서는 틀린 제안에도 불구하고 에이전트가 스스로 필요한 도구를 호출했습니다. 성능이 하락한 시나리오에서는 결정적 턴 제안의 98%가 틀렸습니다.
  • 이득은 도구 호출 증가에서 비롯됨: 제안을 무작위 도구로 바꾸거나 아예 제거해도 H-EPM과 비슷한 성능이 나오며(제안 제거는 3개 모델 중 2개에서 오히려 H-EPM보다 높음), 성공으로 뒤집힌 시나리오는 Base보다 약 2배 많은 도구 호출을 합니다. “도구를 계속 시도하라”는 한 줄의 지시문만으로도 추가 LLM 호출이 거의 없이 H-EPM과 대등하거나 더 좋은 결과를 얻습니다.
  • 정답 다음 도구만으로는 부족: 오라클조차 많은 실패를 남깁니다. 도구 선택 오류는 4%로 줄지만, 나머지는 호출 필요성(예: 도구 호출 없이 포기), 의존성, 인자 오류에서 비롯됩니다.
  • 인사이트 메모리가 최고의 트레이드오프: Insight는 Table 1의 대부분 설정에서 최고 성능이며, 두 도구 그래프 메모리보다 훨씬 많은 설정에서 Base 대비 유의한 향상을 보이고, 거의 모든 설정에서 pass@3가 가장 높으며, LLM 호출은 Base의 1.03배에 머뭅니다. 또한 H-EPM이 악화시킨 시나리오 대부분(모든 의존성 및 인자 실패 포함)을 회복합니다. H-EPM과 결합하면 9개 모델 중 7개에서 오히려 나빠지고 LLM 호출이 2.68배로 늘어나는 반면, Insight + instruction은 3개 절제 모델 모두에서 비오라클 조건 중 최고이며 gpt-oss-20b에서는 오라클마저 넘어섭니다.

의의

도구 사용 에이전트의 메모리 연구는 다음 행동을 처방하는 구조화된 표현 쪽으로 기울어 왔습니다. 이 논문은 도구 그래프 메모리에 대해 유의성 검정을 갖춘 엄밀한 첫 검토를 제공하며, 겉보기 이득이 대체로 추가 계산의 부산물임을 보입니다. 같은 향상은 한 줄의 지시문으로도 얻을 수 있고, 그래프의 안내는 도움이 되기보다 오도하는 경우가 더 많았습니다.

  • 메모리 연구의 엄밀성 제고: 9개 오픈 가중치 모델과 2개 프런티어 모델에 걸친 반복 실행, 쌍체 검정, 비용 집계는 단일 실행의 이득이 얼마나 쉽게 실제 효과로 오인될 수 있는지를 드러내며, 향후 에이전트 메모리 주장에 더 높은 증거 기준을 제시합니다.
  • 부정적 결과를 넘어선 진단: 실패 유형 분류(호출 필요성, 도구 선택, 의존성, 인자)는 완벽한 다음 도구 제안조차 부족한 이유를 설명합니다. 도구 전이는 에이전트에게 도구를 호출할지, 언제 호출할지, 어떤 인자로 호출할지를 알려 주지 못합니다.
  • 실용적이고 일반화 가능한 대안: 인사이트 메모리는 동일한 일화 경험을 상황 수준의 의미 지식으로 증류하며, 학습이 필요 없고 추론 비용 증가가 미미하며 시나리오 간에 전이됩니다. 이 이점은 ExpeL 방식의 인사이트나 성공 궤적만으로 구축한 인사이트에서도 유지되어, 메모리는 다음 도구의 처방보다 부드러운 사전 지식으로 작동할 때 더 효과적이라는 결론을 뒷받침합니다.
